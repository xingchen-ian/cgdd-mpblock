# Templates — the teaching ladder

Three playable scenes, each one step harder, plus a one-dialog way to start a group's
own game from any of them. All of them are **generated from C#** (never hand-edited
YAML), registered in Build Settings, and validated by `./tools/validate.sh`.

---

## Start a game from a template

`MPBlocks > New Game Scene...` (Unity menu bar)

1. Type a **game name** (also the scene/prefab file name).
2. Pick a **starting template**: Empty / Template 1 / Template 2 / Template 3.
3. Set **max players** (2–8) and the **UDP port**.
4. Press **Create scene**.

The window then:

- generates `Assets/Scenes/<GameName>.unity` from the chosen template,
- creates its own `Assets/Settings/NetConfig_<GameName>.asset` with a unique
  session id (e.g. `g03-flagrush-7f12`) — two games never join each other by accident,
- puts the new scene **first and enabled** in Build Settings,
- disables the `Bootstrap` entry (it stays in the list on purpose — removing it makes
  `ProjectSetup` insert it again at position 0).

`./tools/build.sh` now builds that scene; `./tools/validate.sh` validates every
registered scene, enabled or not.

> Templates are registered **disabled**: they are starting points, not the build.

## The ladder

| # | Template | Players | The one idea it teaches | New blocks |
|---|---|---|---|---|
| 1 | `Template1_WorldInteraction` | 2–4 | A client *asks*, the server *decides* — and everyone sees the result | `Interactable`, `SyncedBool`, `InteractToggle` |
| 2 | `Template2_CoopMission` | 2–4 | **State** is replayed for late joiners, **events** are not; a rule lives on the server | `CoopDoor`, `Health`, `DamageOnInteract`, `Scoreboard` |
| 3 | `Template3_ArenaCombat` | 2–4 | Combat itself is server-authoritative: shoot, damage, die, respawn, score | `PlayerShooter`, `Projectile`, `PlayerRespawn`, `PlayerSpawnPoint` |

Every template also carries the four infrastructure objects (`NetworkManager`, `Net`
with `NetBootstrap`, `SessionCanvas`, diagnostics), a shared player prefab, four
`PlayerSpawnPoint`s and a bottom-screen hint.

### Template 1 — world coexistence and interaction

Four players walk around a room with four coloured pads. Walk close and press **E**:
the pad toggles for **everyone**, and a player who joins later sees the current state.

- `Interactable` sends "I want to interact" — it never opens anything itself.
- `SyncedBool` is the pad's state and is server-owned.
- `InteractToggle` is the bridge: server flips the state on approval, every machine
  repaints from `OnChanged`.

```bash
TARGETS=mac BUILD_SCENE=Assets/Scenes/Templates/Template1_WorldInteraction.unity ./tools/build.sh
EXTRA_ARGS="-mp-interact-demo" EXPECT="INTERACT_APPROVED" ./tools/mp-verify.sh
```

### Template 2 — the co-op mission

Two levers: each player pulls one (a lever counts once), and the door slides open.
Behind it a target with 100 HP dies after five approved hits; the kill scores a point.

- The door is a **state** (`SyncedBool`), so a late joiner finds it already open.
- The rule ("both levers, each once") runs on the server in `CoopDoor`.
- The target's health is **state**; the hit is an **event** — the difference decides
  what a newcomer can be shown.

```bash
TARGETS=mac BUILD_SCENE=Assets/Scenes/Templates/Template2_CoopMission.unity ./tools/build.sh
EXTRA_ARGS="-mp-interact-demo" EXPECT="DOOR_OPENED" ./tools/mp-verify.sh
```

### Template 3 — the arena

Four spawn points in the corners of a walled arena, 100 HP each, left mouse button
fires a projectile. The client only asks to shoot; the **server** spawns the bullet,
moves it, applies the damage, credits the kill and tells the dead player where to
respawn. First to five kills is a game rule the group adds on top.

```bash
TARGETS=mac BUILD_SCENE=Assets/Scenes/Templates/Template3_ArenaCombat.unity ./tools/build.sh
EXTRA_ARGS="-mp-shoot-demo" EXPECT="PLAYER_KILLED" ./tools/mp-verify.sh
```

`-mp-shoot-demo` is a test-only flag: the owning client fires at the nearest other
player every ~1.2 s so a headless run can prove hit → damage → death → score without
anyone touching a mouse.

## How a group extends a template

1. Create the game scene from the template (above).
2. Edit only that scene: move objects, add `Interactable`s, change `Health`/`CoopDoor`
   values, wire `OnChanged` in the Inspector.
3. Add game rules as small `NetworkBehaviour` scripts in `Assets/` (never in the
   package) — server-only writes, RPCs ending in `ServerRpc`/`ClientRpc`.
4. `./tools/validate.sh`, `./tools/build.sh`, `./tools/mp-verify.sh`.

Regenerating a template (`MPBlocks > Generate Teaching Templates`) overwrites the
template scenes; game scenes created from the window are independent and survive.

## Bootstrap — the developer sandbox

`Assets/Scenes/Bootstrap.unity` is still generated by `ProjectSetup` and is the
reference demo (levers, door, enemy, crate spawner, latency simulator). It is useful
while working on the blocks themselves. Do not build a game on top of it: the setup
script treats its content as a marker and rebuilds it when the demo objects are
missing.
