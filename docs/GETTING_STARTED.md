# Getting started — build a multiplayer game from zero

Everything below assumes the project already opens (Unity **2022.3.62f3c1**, open the `unity/` folder).

> **Only want the blocks in your own Unity project?** Add the package from its git
> repository: `Window > Package Manager > + > Add package from git URL...` →
> `https://github.com/xingchen-ian/cgdd-mpblock.git#v0.4.1`, then run
> `MPBlocks > Generate Teaching Templates` (the package contains no scenes/prefabs by
> design). The package repository README covers the install steps.

---

## 1. Play the template first (5 min)

Open `unity/Assets/Scenes/Bootstrap.unity`, press **Play**, click **Host**.

| Key | Does |
|---|---|
| type a name | the panel's "Your name" field, before Host / Join |
| WASD | move |
| Right mouse drag | look |
| **E** | interact (levers, enemy) |
| **F2** | network diagnostics (your IP, port, connection events) |
| **F3** | artificial latency |

Pull both levers → the door opens. Press E next to the enemy 5 times → it dies, score +1.

To see two players: `./tools/run-local.sh 3` (host + 3 clients on this machine).

---

## 2. Start your own game

### Fast path (recommended)

1. Unity menu: **`MPBlocks > New Game Scene...`**.
2. Type a game name and pick a starting template (`Empty`, `Template 1` world
   interaction, `Template 2` co-op mission, `Template 3` arena combat), max players
   and port. Press **Create scene**.
3. The window generates the scene from code, creates its own `NetConfig_<GameName>.asset`
   with a unique session id, makes it the first enabled Build Settings scene and
   disables `Bootstrap`. `./tools/build.sh` now builds your game.
4. Open the scene and edit the content. The four infrastructure objects are already
   there — keep them:

| Object | Components | Why |
|---|---|---|
| `NetworkManager` | `NetworkManager`, `UnityTransport` | one per scene, never two |
| `Net` | `NetBootstrap` (assign a `NetConfig`), `LatencySimulator`, `NetDiag` | starts the session, parses `-mp-*` flags |
| `SessionCanvas` | `NetSessionUI` | host / join / leave / refusal reason |
| player prefab | see step 3 | what each player controls |

See [TEMPLATES.md](TEMPLATES.md) for what each template contains and what it teaches.

### Empty-scene path

Choose the `Empty` template in the same window: four infrastructure objects, ground,
light and four `PlayerSpawnPoint`s, nothing else. Do not build a game on top of
`Bootstrap.unity` — the setup script treats its demo objects as markers and rebuilds
it when they are missing. Duplicating it and deleting the demo objects loses that
work on the next build.

## 3. The player prefab

`Assets/Prefabs/Player.prefab` is a working example. Minimum:

| Component | Notes |
|---|---|
| `NetworkObject` | required for anything networked |
| `SyncedTransform` | `Authority = Owner` (a player must not fight their own latency) |
| your controller | movement / input; only acts when `IsOwner` |
| child `Camera` | enabled **only** for the owner |

Then assign it to `NetConfig > Player Prefab`.

**Choosing Transform vs Rigidbody without touching the scene:** the `NetConfig` asset
(select `Net` → its Config field, or open `Assets/Settings/NetConfig_<Game>.asset`) has a
**Player Movement** dropdown:

| Value | Prefab | Use when |
|---|---|---|
| `Transform` | `Assets/Prefabs/Player.prefab` (`SimplePlayerMover`) | no physics needed; flat rooms, simple co-op/puzzle games; cheapest and most predictable |
| `Rigidbody` | `Assets/Prefabs/PlayerRigidbody.prefab` (`RigidbodyPlayerMover`) | gravity, jumping, slopes/stairs, collisions with props, pushable objects |

Both prefabs are generated by the setup script and both are assigned on the NetConfig, so
switching is one dropdown change and affects only the next session spawn. The Rigidbody
prefab is a physics body (Rigidbody + CapsuleCollider, owner-simulated; remote copies
kinematic), so scenes must have colliders on floors/walls for it to stand on. Games created
from the New Game Scene window get the same choice there.

`Player.prefab` itself is deliberately **not** modified: it stays the Transform sample for
template 1 and 2. The physics player is the separate `PlayerRigidbody.prefab`.

Scenes/configs created before this feature are repaired automatically: the setup script
fills `Rigidbody Player Prefab` on every `NetConfig` that does not have one. If you changed
the dropdown before that happened and the field is still empty, run
`MPBlocks > Refresh Project Setup` (or drag `Assets/Prefabs/PlayerRigidbody.prefab` into
`Rigidbody Player Prefab` manually). At runtime, `Player Movement = Rigidbody` with an empty
prefab logs `[MP] WARN PLAYER_PREFAB_FALLBACK` and uses the Transform prefab.

Rigidbody / CharacterController movement in depth: see
[recipes/rigidbody-sync.md](recipes/rigidbody-sync.md) — the synced motion is the
transform, so the authority machine simulates the body and every other machine follows
`SyncedTransform`.

Per-player character look (different avatars/colours for different players):
[recipes/player-appearance.md](recipes/player-appearance.md) — one prefab, visual variants,
and a server-owned `SyncedInt` so late joiners see the right appearance.

**Let players choose their character at session start:** run
`MPBlocks > Add Character Selection to Scene`, edit `Assets/Settings/CharacterRoster.asset`
with your characters, and press Play. The server gives every player a unique character and
a panel lets them change it. Full guide:
[recipes/character-select.md](recipes/character-select.md).

**Rigged / animated characters:** add `PlayerAnimator` (drives the Animator from movement)
and `SyncedAnimator` (replicates `Speed`/`Grounded`/triggers) to the player prefab; each
character is a visual prefab with its own rig and Animator. Full guide:
[recipes/animated-characters.md](recipes/animated-characters.md).

## 4. Add gameplay

> Every MPBlocks block field has an English hover tooltip: rest the mouse on the field
> name in the Inspector. Third-party fields (`NetworkObject`, …) are explained in
> [INSPECTOR_FIELDS.md](INSPECTOR_FIELDS.md).

| Want | Block | Server or client? |
|---|---|---|
| a switch, a door, a ready flag | `SyncedBool` | server sets, clients `RequestSet` |
| a score, health, ammo, a counter | `SyncedInt` / `SyncedFloat` | same |
| "the round just started", a button press | `NetEvent` | client → server, or server → all |
| pick up / open / hit something | `Interactable` | **client requests, server validates** |
| spawning bullets, enemies, pickups | `Spawner` | server only |
| a visible score | `Scoreboard` + `ScoreboardHUD` | server owns, HUD renders |
| damage | `Health` | `ApplyDamage` is **server only** |

Every value block has an `OnChanged` event: wire it in the Inspector and you need no code.

## 4b. Optional: character selection

It is **opt-in per scene** — nothing adds it automatically:

1. Open the scene that has a `NetBootstrap` + `NetConfig`.
2. **MPBlocks → Add Character Selection to Scene**.
3. Save the scene.

That creates `Assets/Settings/CharacterRoster.asset` (four example characters), adds a
`CharacterSelect` object, and gives the player prefabs a `PlayerAppearance` component.

The "Choose your character" panel appears **after** you Host or Join, top-right — not on the
session screen, because it needs your player object to exist first. Each player picks a
different character unless `allowDuplicates` is on.

Picking is free until you press **Confirm**. After that the choice is locked on the server:
the panel collapses to "Playing as Name (locked)" and any further request is refused with
`CHARACTER_SELECT_DENIED … reason=locked`. There is no unlock — restart the session.

## 5. Build and verify

```bash
./tools/validate.sh     # static checks on EVERY registered scene — must say errors=0
./tools/build.sh        # mac + windows, first enabled Build Settings scene
./tools/mp-verify.sh    # 1 server + 2 clients must connect and agree on state
```

`mp-verify.sh` exiting 0 is the definition of "multiplayer still works".
`CLIENTS=3 ./tools/mp-verify.sh` verifies the four-player exhibition setup.

Tooling switches (both scripts print them in the header):

```bash
TARGETS=mac ./tools/build.sh                      # mac only, no Windows build
TARGETS=mac BUILD_SCENE=Assets/Scenes/Templates/Template1_WorldInteraction.unity ./tools/build.sh
TOOL_BUILD=1 ./tools/build.sh                     # ship the tool: Bootstrap + templates only
EXTRA_ARGS="-mp-interact-demo" EXPECT="INTERACT_APPROVED" ./tools/mp-verify.sh
```

`EXPECT` is a pipe-separated list of regexes that must appear in the server log, so a
template's own gameplay (door opened, player killed) can be asserted, not just "they
connected". See [TEMPLATES.md](TEMPLATES.md) for the three templates' commands.

## 6. The three questions that decide every design

1. **Who owns this state?** Players own their own body; the server owns everything else.
2. **Is it a state or an event?** A state is true now and stays true (door open). An event happened once (a button was pressed).
3. **What does a late joiner see?** States are replayed for them. **Events are not.** If a newcomer must see it, it is a state.

## 5b. Building a co-op mission from an empty scene

1. **MPBlocks → New Game Scene...** — name it, set Max Players, Create. That writes the scene,
   its `NetConfig`, and the infrastructure (NetworkManager, NetBootstrap, session panel, ground).
2. *(optional)* **MPBlocks → Add Character Selection to Scene**.
3. Add four spawn points: empty GameObjects named `SpawnPoint_1..4`, spread apart, each with a
   `PlayerSpawnPoint` component. Without them every player spawns on the origin, inside each other.
4. **MPBlocks → Add Co-op Door Kit to Scene** — two levers, a sliding door and a wired `CoopDoor`.
5. Select `Door` → `Co-op Door` → `Window Seconds` (2.5 by default). Both levers must be pulled
   inside that window or the levers spring back, so one player cannot do it alone.
6. File → Build Settings → Add Open Scenes (only needed for player builds).
7. Play → Host, and join with a second player. Pull one lever; a second player must pull the other
   within the window.

## 5c. Sound: the placeholder library

`MPBlocks > Audio > Generate Placeholder Sounds` (also runs automatically on editor load)
writes nine ready-to-use **.wav files** into `Assets/Audio`. They are synthesised
placeholders, not copyrighted assets, so they are safe to ship in a class project. The files
are real 16-bit PCM audio — open one in the Inspector and you can play it.

| Clip | Sounds like | Put it on |
|---|---|---|
| `Interact_Approved` | short bright click | `InteractSound > Approved Clip` |
| `Interact_Denied` | low thud | `InteractSound > Denied Clip` |
| `Shot_Fire` | noise burst | bullet prefab, `AudioOneShot` trigger `OnEnable` |
| `Hit_Damage` | dull impact | player prefab, `AudioOneShot` trigger `OnHealthChanged` |
| `Player_Death` | falling tone | player prefab, `AudioOneShot` trigger `OnDeath` |
| `Player_Respawn` | rising chime | call `Play()` from your respawn code |
| `Pickup` | two-tone up | the pickup prefab |
| `Door_Open` | low slide | the door object |
| `Score_Point` | bright ding | call `Play()` when a point lands |

To use one: add `Audio One Shot`, drag the clip into **Clip**, pick a **Trigger**. Several
`AudioOneShot` components may sit on the same object (hit and death, for example).
Replace any clip with your own file by dragging it into the same slot — nothing looks assets
up by name.

### Silent audio

`./tools/validate.sh` fails when an audio file under `Assets` has no samples. That covers the
trap from an earlier toolkit version, where clips were saved as `.asset` shells with length 0:
they looked fine in the Project window and played nothing.

## 6b. Updating the toolkit (no terminal needed)

`unity/Assets/Editor/MPBlocksUpdater.cs` adds a menu that does the whole update:

| Menu | Does |
|---|---|
| **MPBlocks > Package > Check for Update** | reads the tag list from GitHub, compares with what is installed |
| **MPBlocks > Package > Update to Latest** | clears the cache, rewrites the dependency, re-resolves |
| **MPBlocks > Package > Reinstall Current Version** | same version, clean cache (use when something looks stale) |

One click replaces "edit manifest.json, delete Library/PackageCache, restart". If the package
is installed from a git URL in another project, copy that one file into that project's
`Assets/Editor/` folder once and the menu works there too.

After an update Unity recompiles by itself. If the MPBlocks menu still looks old, restart Unity
once — assemblies from a git package are only reloaded on a full resolve.

## 7. When it does not work

| Symptom | Check |
|---|---|
| nothing happens on Play | is `NetBootstrap` in the scene? press Host in the session panel |
| clients cannot join | `F2` panel: compare the host's IP with what the client typed |
| join refused | the panel shows the reason (`server full`, `wrong game`) |
| a value does not update for others | was it set on the server? `StateHash` logs `STATE_HASH_MISMATCH` |
| "works on my machine" | `./tools/validate.sh`, then grep the log for `[MP]` |
| Windows cannot connect at all | the firewall prompt was cancelled — allow the app |

Logs: `[MP] …` lines in the player log or `out/logs/`.
